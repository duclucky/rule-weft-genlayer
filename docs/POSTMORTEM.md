## Failures that changed verification

- A Chrome native date control could contain a value without updating React
  state. The failing regression led to named controls and FormData submission.
- Connection success did not prove signing. Some OKX sends returned4001 without
  a hash; canonical records, nonce and balances were checked before retrying.
  Owner direct clicks ultimately signed. The underlying rejection cause remains
  unknown; it is not attributed to a locked wallet or a network outage.
- A proxy omitted the nested quorum-reached control code, causing successful
  finality to look failed. A raw/proxy comparison reproduced it. Only the known
  safe code is now projected; unknown diagnostics and validator config stay out.
- UNDETERMINED can precede finalization. The adapter now retains and resumes the
  existing hash through bounded uncertainty rather than inviting another send.
- A finalized leader return can still be majority-disagreed and unapplied.
  Receipt interpretation requires actual consensus agreement and canonical state.
- Vercel READY did not prove its API worked. Frontend-local dependency declarations,
  a valid Node ESM import and a native emitted-API check fixed real deployment
  failures before root/proxy/browser verification.
- A single overview paragraph did not satisfy the requested How-to presentation.
  The submitted revision now contains nine separate heading/instruction steps,
  verified again after submission while the revision was locked.

## Honest boundaries and milestone headroom

V1 is a three-rule constitutive protocol on resettable Studio Dev. It does not
prove external execution, legal authority, privacy compliance, general ODRL
conformance, production audit or adoption. Author setup and secondary verdict
classes have script execution plus UI tests; their actual Chrome execution is
not claimed. Production-origin wallet signatures are not claimed.

After V1 is accepted, the next substantial milestone is an authenticated
agent-tool execution gateway consuming exact policy/version/request-bound
finalized permits at its actual write boundary. It needs independent issuer/origin
binding, expiry, revocation, anti-replay and live enforcement evidence. LangGraph,
OPA/Envoy and DAOhaus are proposed consumers, not existing adopters. Renaming,
restyling, adding a mirror guard or enlarging the prompt is not that milestone.
